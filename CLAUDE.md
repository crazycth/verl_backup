# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**verl** (Volcano Engine Reinforcement Learning for LLMs) is a flexible, efficient RL training framework for large language models by ByteDance. It supports PPO, GRPO, DAPO, PRIME, and 20+ other RL algorithms with FSDP/FSDP2/Megatron-LM backends. Key paper: HybridFlow (EuroSys 2025).

## Common Commands

### Installation
```bash
pip install -e .[test,vllm]    # with vLLM backend
pip install -e .[test,sglang]  # with SGLang backend
```

### Linting & Formatting
```bash
pre-commit install
pre-commit run                              # staged changes only
pre-commit run --all-files                  # all files
pre-commit run --all-files ruff             # ruff only
pre-commit run --all-files autogen-trainer-cfg  # regenerate config YAMLs
```

Ruff config: line-length=120, rules: E/F/UP/B/I/G (see `pyproject.toml`).

### Testing
```bash
# CPU-only tests (file name pattern: test_*_on_cpu.py)
pytest tests/path/to/test_something_on_cpu.py

# GPU tests (all other test files under tests/)
pytest tests/path/to/test_something.py

# Multi-GPU distributed tests
# See tests/special_distributed/

# End-to-end tests
# See tests/special_e2e/
```

Test naming convention: files ending in `_on_cpu.py` run on CPU; all others require GPU.

### Docs
```bash
pip install -r requirements-docs.txt
cd docs && make clean && make html
python -m http.server -d _build/html/
```

## Architecture

### Core Data Protocol (`verl/protocol.py`)
`DataProto` is the universal data transfer object between all workers. It wraps `TensorDict` and supports padding, batching, chunking, and distributed allgather. Every worker consumes and produces `DataProto` instances.

### Configuration System (`verl/trainer/config/`)
- Dataclass-based `BaseConfig` with Mapping interface and frozen fields (`verl/base_config.py`)
- Hydra composable configs under `verl/trainer/config/` with sub-dirs: `actor/`, `critic/`, `data/`, `engine/`, `model/`, `optim/`, `reward_model/`, `rollout/`
- `_generated_*.yaml` files are auto-generated by the `autogen-trainer-cfg` pre-commit hook — do not edit manually
- Algorithm config with strict mypy checking: `verl/trainer/config/algorithm.py`

### Ray-Based Orchestration (`verl/single_controller/`)
The single-controller pattern uses Ray to orchestrate distributed workers. `RayPPOTrainer` (`verl/trainer/ppo/ray_trainer.py`) is the main training loop that coordinates actor, critic, rollout, and reward workers.

### Worker Architecture (`verl/workers/`)
- **Actor** (`workers/actor/`): Policy model training (forward + backward)
- **Critic** (`workers/critic/`): Value function training
- **Rollout** (`workers/rollout/`): Generation via vLLM, SGLang, or naive backends
- **Reward Model** (`workers/reward_model/`): Reward scoring
- **Sharding Manager** (`workers/sharding_manager/`): GPU placement and model resharding between training and inference

### Training Backends (`verl/workers/engine/`)
- FSDP (PyTorch Fully Sharded Data Parallel)
- FSDP2 (next-gen)
- Megatron-LM (for very large models with expert parallelism)

### RL Algorithms (`verl/trainer/ppo/`)
- `core_algos.py`: Core algorithm implementations (PPO, GRPO, etc.) — has strict mypy
- `reward.py`: Reward computation — has strict mypy
- `ray_trainer.py`: Main training loop orchestration
- `metric_utils.py`: Training metrics

### Recipes (`recipe/`)
Standalone training recipes that compose verl components for specific algorithms (DAPO, PRIME, entropy-based methods, off-policy distillation, etc.). These are not part of the `verl` package itself.

### Third-Party Integrations (`verl/third_party/`)
Patches and adapters for vLLM and SGLang inference engines.

## Code Quality

### Pre-commit hooks (all must pass):
1. **ruff**: Lint + format (line-length 120)
2. **mypy**: Type checking (strict only for `verl.trainer.config.algorithm`, `verl.trainer.ppo.core_algos`, `verl.trainer.ppo.reward`, `verl.workers.reward_manager`)
3. **autogen-trainer-cfg**: Regenerates flattened config YAMLs from Hydra configs
4. **check-docstrings**: Docstring coverage verification
5. **check-license**: Apache 2.0 license headers required on files in `examples/`, `recipe/`, `scripts/`, `tests/`, `verl/`, and `setup.py`

### Environment Variables
- `VERL_USE_MODELSCOPE=true`: Download models from ModelScope instead of HuggingFace
- `VERL_USE_EXTERNAL_MODULES`: Comma-separated list of external modules to import at init

### Device Support
The codebase supports both CUDA and Ascend NPU. NPU detection is automatic via `verl/utils/device.py`, and NPU-specific patches are applied in `verl/__init__.py`.
